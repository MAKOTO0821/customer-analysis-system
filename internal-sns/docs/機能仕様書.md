# 社内SNS「Connect」機能仕様書

## 1. 概要

本アプリケーションは、X（旧Twitter）風のUI/UXを持つ社内向けSNSである。
アカウント登録、フォロー、非公開アカウント（鍵アカ）、投稿、リプライなど、社内コミュニケーションに必要な基本機能を備える。

- アプリ名: Connect
- 対象: 社内利用（イントラネット／社内ネットワークでの利用を想定）
- データベース: SQLite（ファイルベース、サーバ管理不要）

## 2. 技術スタック

| 分類 | 技術 |
| --- | --- |
| フレームワーク | Next.js 16（App Router / Turbopack） |
| 言語 | TypeScript |
| UI | React 19 / Tailwind CSS v4 |
| DB | SQLite |
| ORM | Prisma 6 |
| 認証 | Auth.js（NextAuth v5）Credentials Provider + JWTセッション |
| パスワードハッシュ | bcryptjs |
| バリデーション | Zod |

フロントエンドとバックエンドはNext.jsの単一プロジェクトで実装しており、画面（App Router のページ）とAPI（Route Handlers）が同一リポジトリに同居する構成である。

## 4. データモデル

Prismaスキーマ（`prisma/schema.prisma`）に基づく主要テーブルは以下の通り。

### User（ユーザー）
| カラム | 型 | 説明 |
| --- | --- | --- |
| id | String | 主キー（cuid） |
| username | String | ユーザー名（一意、ログインID兼用） |
| email | String | メールアドレス（一意） |
| passwordHash | String | bcryptハッシュ化されたパスワード |
| displayName | String | 表示名 |
| bio | String | 自己紹介文（最大160文字） |
| avatarUrl | String | アイコン画像URL（任意） |
| isPrivate | Boolean | 鍵アカウントフラグ |
| createdAt | DateTime | 登録日時 |

### Follow（フォロー関係）
| カラム | 説明 |
| --- | --- |
| followerId | フォローする側のユーザーID |
| followingId | フォローされる側のユーザーID |
| status | `PENDING`（申請中） / `ACCEPTED`（承認済み） |

`(followerId, followingId)` の組み合わせで一意。相手が鍵アカウントの場合は `PENDING` で作成され、承認されると `ACCEPTED` に更新される。公開アカウントの場合は即座に `ACCEPTED` となる。

### Block（ブロック関係）
| カラム | 説明 |
| --- | --- |
| blockerId | ブロックした側のユーザーID |
| blockedId | ブロックされた側のユーザーID |

ブロックが成立すると、双方向のFollow関係は自動的に削除される。

### Tweet（投稿）
| カラム | 説明 |
| --- | --- |
| content | 本文（最大280文字） |
| authorId | 投稿者ID |
| parentId | リプライ先の投稿ID（通常投稿の場合はnull） |

`parentId` による自己参照で、通常投稿とリプライを同一テーブルで管理する。

### Like（いいね）
| カラム | 説明 |
| --- | --- |
| userId | いいねしたユーザーID |
| tweetId | 対象投稿ID |

`(userId, tweetId)` の組み合わせで一意。

## 5. 機能一覧

### 5.1 アカウント作成
- 画面: `/register`
- 入力項目: 表示名、ユーザー名（英数字・アンダースコア、3〜20文字）、メールアドレス、パスワード（8文字以上）
- ユーザー名・メールアドレスは重複不可。
- パスワードはbcryptでハッシュ化して保存（平文保存はしない）。
- 登録完了後、自動的にログインしホーム画面へ遷移する。

### 5.2 ログイン／ログアウト
- 画面: `/login`
- ユーザー名とパスワードによる認証（Auth.js Credentials Provider）。
- セッションはJWT方式。ログイン状態はCookieで保持され、ブラウザを閉じても一定期間保持される。
- サイドバーの「ログアウト」ボタンからログアウト可能。ログアウト後は `/login` へリダイレクトされる。
- 未ログイン状態でログイン必須画面にアクセスした場合は自動的に `/login` へリダイレクトされる。

### 5.3 フォロー／フォロー解除
- 相手が公開アカウントの場合: 「フォローする」ボタンを押すと即座にフォロー成立（`ACCEPTED`）。
- 相手が鍵アカウント（非公開）の場合: フォローリクエストとして送信され、状態は「リクエスト済み」と表示される。相手が承認するまでフォローは成立しない。
- フォロー中のユーザーに対しては「フォロー中」ボタンが表示され、ホバー時に「フォロー解除」に変化する。クリックでフォロー解除。
- リクエスト中の場合も同ボタンから取り消し可能。

### 5.4 ブロック
- プロフィール画面の「ブロック」ボタンから実行（確認ダイアログあり）。
- ブロックすると、双方のフォロー関係が解除され、以後お互いに以下が制限される。
  - 相手のプロフィール・投稿の閲覧不可（「このユーザーはあなたをブロックしています」等のメッセージを表示）
  - フォロー不可
  - 投稿への返信・いいね不可
- 「ブロック中」ボタンから解除可能。

### 5.5 フォローリクエスト管理（鍵アカ用）
- 画面: `/follow-requests`
- 自分宛の保留中フォローリクエスト一覧を表示。
- 各リクエストに対して「承認」「拒否」を選択可能。
- 保留中のリクエスト件数はサイドバーにバッジ表示される。

### 5.6 ユーザーのプロフィール編集
- 画面: `/settings/profile`
- 編集可能項目: 表示名、自己紹介（160文字以内）、アイコン画像URL、鍵アカウント設定（ON/OFF）。
- ユーザー名・メールアドレスは編集不可（初期実装ではセキュリティ・シンプルさを優先し対象外）。

### 5.7 鍵アカウント（非公開アカウント）機能
- プロフィール編集画面のトグルでON/OFF切り替え可能。
- ONの場合、以下のように投稿・プロフィール情報の閲覧が制限される。
  - 承認済みフォロワー、および本人のみ投稿一覧を閲覧可能。
  - 非フォロワーがプロフィールを開くと「このアカウントは非公開です」というロック表示となり、投稿は表示されない。
  - 新規フォローは即時反映されず、フォローリクエストとして送信される。
- 既に承認済みのフォロワーは、後から鍵アカウントに切り替えても引き続き閲覧可能（X等の一般的な挙動に準拠）。

### 5.8 投稿（ツイート）
- ホーム画面上部の投稿フォームから作成。最大280文字。
- 投稿は自分のプロフィールとホームタイムライン（自分＋フォロー中ユーザーの投稿）に表示される。
- 自分の投稿は削除可能（確認ダイアログあり）。削除するとリプライも連動して削除される。

### 5.9 リプライ機能
- 投稿詳細画面（`/tweet/[id]`）の返信フォームから投稿。
- リプライ先が非公開アカウントかつ未フォロー（または未承認）の場合、あるいはブロック関係にある場合はリプライ不可。
- 投稿カードには「返信先: @username」が表示され、リプライであることが分かる。
- 各投稿にはリプライ件数が表示され、クリックで詳細画面（スレッド表示）に遷移する。

### 5.10 いいね機能（追加機能）
- 各投稿にいいねボタンを設置。ワンクリックでON/OFFをトグル。
- 閲覧権限のない投稿（非公開アカウントの非フォロワー等）にはいいね不可。

### 5.11 ユーザー検索（追加機能）
- 画面: `/search`
- ユーザー名・表示名の部分一致でユーザーを検索。
- 検索結果からそのままフォロー操作が可能。
- ブロック関係にあるユーザーは検索結果に表示されない。

### 5.12 タイムライン（ホーム）
- 自分自身の投稿と、フォロー中（承認済み）ユーザーの投稿を新着順に表示。
- リプライも通常投稿と同様にタイムラインへ表示される。

## 7. API仕様（Route Handlers）

すべて `Content-Type: application/json` で通信する。認証必須のAPIは、未ログイン時に `401` を返す。

| メソッド | パス | 説明 | 認証 |
| --- | --- | --- | --- |
| POST | `/api/register` | アカウント新規作成 | 不要 |
| GET/POST | `/api/auth/[...nextauth]` | Auth.js 標準エンドポイント（ログイン/ログアウト/セッション取得等） | - |
| PATCH | `/api/profile` | 自分のプロフィール更新 | 必須 |
| GET | `/api/users?q=キーワード` | ユーザー検索 | 必須 |
| GET | `/api/users/[username]` | ユーザー情報・関係性・統計取得 | 任意 |
| GET | `/api/users/[username]/tweets` | 指定ユーザーの投稿一覧取得（閲覧権限を考慮） | 任意 |
| POST | `/api/users/[username]/follow` | フォロー（相手が非公開ならリクエスト） | 必須 |
| DELETE | `/api/users/[username]/follow` | フォロー解除／リクエスト取消 | 必須 |
| POST | `/api/users/[username]/block` | ブロック | 必須 |
| DELETE | `/api/users/[username]/block` | ブロック解除 | 必須 |
| GET | `/api/follow-requests` | 自分宛の保留中フォローリクエスト一覧 | 必須 |
| POST | `/api/follow-requests/[id]` | リクエスト承認/拒否（`{ action: "accept" \| "reject" }`） | 必須 |
| GET | `/api/tweets` | ホームタイムライン取得 | 必須 |
| POST | `/api/tweets` | 投稿作成（`{ content, parentId? }`） | 必須 |
| GET | `/api/tweets/[id]` | 投稿詳細＋リプライ一覧取得（閲覧権限を考慮） | 任意 |
| DELETE | `/api/tweets/[id]` | 投稿削除（自分の投稿のみ） | 必須 |
| POST | `/api/tweets/[id]/like` | いいねのトグル | 必須 |

## 8. 認可（閲覧権限）ロジック

投稿・プロフィールの閲覧可否は `src/lib/relationship.ts` の `canViewProfile` 関数で一元的に判定している。

1. 本人自身の場合 → 常に閲覧可能。
2. ブロック関係（自分がブロックした／相手にブロックされた）がある場合 → 閲覧不可。
3. 相手が公開アカウントの場合 → 閲覧可能。
4. 相手が鍵アカウントの場合 → 自分が承認済みフォロワーである場合のみ閲覧可能。

投稿の閲覧・いいね・リプライ・タイムライン表示など、投稿に関わるすべての操作はこのロジックを経由して権限チェックを行う。

## 9. セキュリティ上の配慮

- パスワードはbcryptjsでハッシュ化して保存し、平文は保持しない。
- 認証はJWTベースのセッションCookie（httpOnly）で管理。
- すべての更新系API（POST/PATCH/DELETE）はサーバー側で改めてログイン状態・権限をチェックしており、クライアント側の表示制御のみに依存しない。
- Zodによる入力バリデーションをAPI層で実施。

## 10. セットアップ・起動方法

```bash
# 依存パッケージのインストール
npm install

# DBスキーマの反映（初回・スキーマ変更時）
npx prisma db push

# 開発サーバー起動
npm run dev
```

起動後、`http://localhost:3000` にアクセスするとログイン画面が表示される。

環境変数は `.env` に以下を定義している。

| 変数名 | 説明 |
| --- | --- |
| `DATABASE_URL` | SQLiteファイルのパス（`file:./dev.db`） |
| `AUTH_SECRET` | Auth.jsのセッション署名用シークレット |
